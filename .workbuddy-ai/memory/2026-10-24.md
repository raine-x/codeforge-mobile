## 方案已产出：`docs/android-native-plan.md`

**三个核心判断**
1. **后端零改动**——36 REST + 35 WS 消息类型即完整契约，原生 UI 只是换客户端。内核只需加 `port:0` 随机绑定 + stdout 打 `PORT=xxxxx`（约 40 行）。
2. **三语言难度差一个数量级**：Python（Chaquopy，JNI 进程内，**不需 exec**）< Java（ECJ+D8 纯 Java 跑在 ART 上，**不需 exec**）<< Go（编译器是原生二进制且要 fork 子进程，**必须 exec**）。这是本方案最重要的洞察。
3. **多语言支持不在内核，在 PATH**——`run_command` 只跑 shell 命令，不需要项目类型识别，`pkg/tools` 零改动。

**W^X 限制**：Android 10 起禁止 exec app 私有目录文件，开关是 targetSdk（≤28 不限制，≥29 生效）。降 28 可复用 Termux/proot 生态；保 36 需自研 memfd+execveat 桥，无成熟先例。Android 15/16 只要求 targetSdk≥24，故 28 仍可安装，但 Play 上架要求 ≥35。

**P0 实验（必须先跑，决定路线）**
- E1：nativeLibraryDir 能否 exec 静态二进制（busybox 改名 libbb.so）
- E2：proot 在 targetSdk 28 下能否跑 rootfs 内程序（proot 走 mmap PROT_EXEC 而非 execve，但 SELinux 对 app_data_file 的 PROT_EXEC 同样可能拦 —— **不可靠推理，必须实测**）
- E3：端口握手
- E4：FGS 改 specialUse 后存活 8 小时

**UI 分期**：P0 能对话（含审批卡片，否则 agent 卡死）→ P1 能用（模型/工作区/设置）→ P2 完整（diff/附件/子智能体/插件）。
**横竖屏**：Compact<600dp 单栏+底部导航；Medium 600-840 双栏；Expanded≥840 三栏。`configChanges` 已声明 orientation|screenSize，Activity 不重建。

**用户已确认**：多语言深度取「编译+运行」，不含 LSP。
**用户待决策**：UI 框架（建议 Compose，他问过「Compose 能做高级动画吗」——已答：能，共享元素/spring/lookahead 都有）、targetSdk（建议 28）。
