## 真机验证发现的隐藏 bug（12:45）

**`seedDeepSeekIfEmpty` 置位顺序反了**：
```kotlin
seededDeepSeek = true      // 先置位
val a = api ?: return      // 再判空
```
内核未就绪时 `api` 为 null → return，但标志已置位 → **本进程内永不重试**。
表现：providers.yaml 有、models.yaml 不存在、apply 跟着失败。

**修**：先取 api 再置位；`saveModelFull` 返回值接住并弹横幅。

**修后 `pm clear` 验证**：models.yaml 出现完整规格（ctx_in/ctx_out/vision/video）。

**通用教训**：「一次性标志 + 资源判空」的顺序，判空必须在前。这类 bug 在首次启动
（内核未就绪）时必现，但重启一次就好，所以很容易被误判成「偶发」。

## LaTeX 高度真根因（14:10–14:45）

**`contentH.toDp()` 是 px→dp（除以 density），但 reportH 报的是 CSS px ≈ dp**
→ density=2 时容器只有一半高 → 矩阵第二行/cases 第一列被裁、分式压扁。
改用 `contentH.dp` 后行内公式完全正确。

**正反馈坑**：maxH 里把 `documentElement` 高度算进最大值 → html 高度=视口高度 →
报高→容器更高→再报高，撑成大片空白。只用 body.scrollHeight 与 .blk 的 bottom。

**触顶**：尾部 `fillParentMaxHeight(0.92f)` 无条件生效 → 内容不足一屏也能拉出空白。
改成先比内容高度与视口高度。

**未解决**：块级公式仍有空白块；自研 LaTeX 子集能力有限（已补 \ge/\le 等简写），
彻底可靠需换离线 KaTeX。


## 公式框自己拉长：scrollHeight 的下限语义（14:50–15:05，已解决）

**根因**：`scrollHeight` = 内容高度，**但至少等于 clientHeight**。
公式块内容比视口矮时，`body.scrollHeight` 返回视口高度 →
容器变高 → 视口变高 → scrollHeight 变高 → 报更高 → 无限拉长。

**修**：`<body><div id=wrap>…</div></body>`，只测 `wrap.offsetHeight`。
wrap 是普通块，高度严格等于内容，与视口无关，环就断了。
ResizeObserver 也改观察 wrap；reportH 去掉 +6（UI 层已有）。

**验证**：间隔 4 秒两帧截图主体区域逐像素一致；矩阵两行完整、分式正确、
200dp 空白消失。

**教训**：`scrollHeight` 有 clientHeight 下限，用它做「内容高度」度量时，
只要容器高度可变就会正反馈。要测内容高度必须用一个不受外部约束的内层元素。
